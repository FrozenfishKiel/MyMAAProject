# DQN 强化学习算法设计详解

在抛开前期的基于CV和API的卡组选择后，核心的游戏内即时决策完全由深度强化学习（Deep Q-Network, DQN）实现。以下是DQN具体如何工作以及每一步的具体设计。

## 1. 强化学习的四大要素设计

在 `pvz_env.py` 中，定义了与DQN交互的环境 `PVZEnv`。它的核心是将《植物大战僵尸》抽象为一个马尔可夫决策过程（MDP）。

### 1.1 状态空间 (State/Observation Space)
代理在每个时刻 `t` 会接收一个状态 `s_t`，具体包含三部分：
1. **Lawn (草坪网格)**: 一个 `5 × 9 × 12` 的3D矩阵。其中12个通道分别表示10种植物和2种僵尸的**独热编码(One-hot)**。如果 `(row, col, 0)` 为 1，表示该位置有一个“豌豆射手”。
2. **Sun (阳光资源)**: 当前积攒的阳光数值（标量）。
3. **Plants Remaining (植物冷却/库存)**: 一个长度为10的数组，代表每种植物还能放置多少个（模拟CD或库存限制）。

### 1.2 动作空间 (Action Space)
DQN需要在给定的状态下做出决策。动作空间是一个巨大的离散空间：
- 动作定义为：`(row, col, plant_type)`。
- 总组合数：`5（行） × 9（列） × 10（植物种类） = 450` 种可选动作。
- 在每个时间步，DQN网络会输出这 450 个动作对应的预期收益（Q值），代理选择Q值最高的动作（利用），或者随机选择一个动作（探索）。

### 1.3 奖励机制 (Reward Function)
奖励是引导DQN学习“怎么赢”的唯一指标，在 `_update_state` 方法中定义：
- **击杀奖励 (正向)**: 植物的攻击逻辑被简化为每回合扫描同行的僵尸。一旦消灭僵尸，根据植物类型给予不同奖励。例如，豌豆射手击杀 +140，寒冰射手击杀 +120，食人花近战吞噬 +150。
- **存活失败 (负向)**: 如果在任何一行中，僵尸走到了第0列（最左侧，代表进入房子），游戏立刻结束 `self.game_over = True`，并且给予 `-1000` 的巨大惩罚。
- **无效动作惩罚 (负向)**: 在 `step` 方法中，如果DQN尝试在一个已经有植物的格子上放植物、阳光不够、或者库存不够（`_is_valid_action` 返回 False），直接给予 `-10` 的惩罚，迫使网络学会游戏的基础规则。

### 1.4 状态转移 (State Transition)
当DQN输出一个有效动作后，环境会调用 `_place_plant` 消耗阳光并放置植物。随后环境内部模拟僵尸的生成（每5个回合生成一次）、植物发射子弹扣除僵尸血量（简化为直接让僵尸消失）、以及僵尸向前移动并啃食植物的逻辑，最后返回下一个状态 `s_{t+1}`。

## 2. 神经网络结构 (DQN Model)

在 `dqn_agent.py` 中，定义了用于拟合动作价值函数 `Q(s, a)` 的神经网络结构。因为状态包含空间图像数据（草坪）和一维数值数据（阳光、库存），网络采用了**多模态融合架构**：

### 2.1 空间特征提取 (CNN部分)
输入是草坪的状态 `(batch, 12, 5, 9)`。
网络使用了3层卷积来提取战局的空间特征：
1. `Conv2d(12, 32, kernel=3, padding=1)` + `ReLU`
2. `Conv2d(32, 64, kernel=3, padding=1)` + `ReLU`
3. `Conv2d(64, 64, kernel=3, padding=1)` + `ReLU`
最后使用 `AdaptiveAvgPool2d((1, 1))` 将特征图压缩为一个长度为64的一维向量。这让网络能够“看懂”场上哪里有危险、哪里有防守空缺。

### 2.2 状态融合与决策头 (FC部分)
- **拼接**: 将 CNN提取出的 64维向量、1维的阳光数值、10维的植物库存拼接起来，形成一个长度为 75 的一维向量。
- **全连接层**: 将 75 维向量输入到隐藏层节点为 512 的全连接层（带 ReLU 激活）。
- **输出层**: 最后映射到维度为 450 的输出层。这450个数值就是当前状态下，执行每个动作的 **Q值估计**。

## 3. 训练流程 (Training Loop)

在 `train` 函数和 `train_step` 方法中，定义了 DQN 的训练闭环：

1. **探索与利用 (ε-greedy)**: 
   代理以 `epsilon` 的概率进行随机瞎点（探索），以 `1 - epsilon` 的概率相信神经网络的输出选Q值最大的动作（利用）。`epsilon` 随着训练次数的增加从 1.0 缓慢衰减至 0.05。

2. **经验回放 (Replay Buffer)**: 
   代理并不会立刻用刚刚发生的一步来更新网络，而是将这步经历 `(state, action, reward, next_state, done)` 存入一个容量为 50000 的记忆池（`ReplayBuffer`）。

3. **网络参数更新 (Bellman Equation)**:
   - 每次训练时，从记忆池中随机抽取 `batch_size=64` 条经验。
   - 使用 **Target Net（目标网络）** 计算下一个状态的最大Q值：`max Q_target(s_{t+1}, a)`。
   - 根据贝尔曼方程计算目标Q值：`y = reward + gamma * (1 - done) * max Q_target(s_{t+1}, a)`。
   - 使用 **Policy Net（策略网络）** 计算当前状态执行该动作的预测Q值：`Q_policy(s_t, a_t)`。
   - 将预测Q值和目标Q值计算均方误差损失（`MSELoss`），通过反向传播（`Adam` 优化器，学习率 `1e-4`）更新 **Policy Net** 的权重。

4. **目标网络同步 (Target Network Update)**:
   为了保证训练过程稳定，避免目标“自己追自己”导致的发散，每隔 2000 步（`target_update`），直接将 **Policy Net** 的参数硬拷贝复制给 **Target Net**。

## 4. 部署植物的完整执行链路

在代码中，“部署（放置）植物”的流程是将神经网络抽象的数学输出，一步步转化为游戏环境中的具体操作。这个流程可以分为 4 个核心步骤：

### 4.1 大脑输出与动作解码 (Action Decoding)
当需要决定下一步干什么时，状态输入给 DQN 网络，网络会在最后的全连接层输出一个长度为 **450** 的一维数组（代表预测的 Q 值）。
系统会找到这 450 个数字中**最大值对应的索引**（假设索引值为 `action_idx`），然后通过数学取模和整除操作，将其解码为 3 个维度的具体坐标：
- **行 (Row)**: `action_idx // (9 * 10)` （结果为 0~4）
- **列 (Col)**: `(action_idx % (9 * 10)) // 10` （结果为 0~8）
- **植物类型 (Plant Type)**: `action_idx % 10` （结果为 0~9，对应豌豆射手、向日葵等）

### 4.2 环境合法性校验 (Validation)
指令传达给游戏环境（`pvz_env.py` 的 `step()` 函数）后，环境不会立刻放置，而是先调用 `_is_valid_action` 进行严格的三重检查：
1. **位置是否被占用**：检查 `lawn[row, col]` 这个格子上是不是已经有植物了。
2. **阳光是否充足**：检查当前右上角的 `sun` 总量，是否大于或等于该植物的造价（比如豌豆射手需要100阳光）。
3. **冷却/库存是否有剩余**：检查 `plants_remaining[plant_type]` 是否大于 0。

**极其严厉的惩罚机制**：如果这三项中有任何一项不满足（即这是一个违规动作），系统会立刻给出 `-10` 的负奖励，并且**直接终止当前这局游戏的训练 (`done = True`)**。这意味着 AI 必须最优先学会游戏的规则（不乱点、不透支），否则它根本活不到去打僵尸的阶段。

### 4.3 扣除资源与物理放置 (Placement)
如果校验通过，环境会调用 `_place_plant` 执行真正的放置逻辑：
- **修改网格状态**：将三维矩阵对应位置标记为有植物：`self.lawn[row, col, plant_type] = 1`。
- **扣除阳光**：`self.sun -= 该植物的花费`。
- **扣除库存**：`self.plants_remaining[plant_type] -= 1`。

### 4.4 推进游戏时间线并结算 (Game Tick & Combat)
植物放下去之后，游戏时间会向前推进一个回合（`_update_state`）：
1. **阳光生产**：场上每有一个向日葵，总阳光增加 25。
2. **植物攻击**：环境会扫描刚才部署植物的这一行。如果是豌豆射手，它会查找前方有没有僵尸的标记（`>0`），如果有，直接将该僵尸从矩阵中抹去（这里的战斗逻辑做了简化，没有子弹飞行过程，植物直接“秒杀”视野内的首个僵尸），并给 AI 加上相应的击杀奖励。
3. **僵尸推进**：剩下的僵尸向前移动一格；如果僵尸前方格子里有植物（也就是僵尸碰到了刚部署的植物），僵尸会停下来，并且直接把植物吃掉（将矩阵中该植物的标记清零，如果是坚果墙则有概率挡住）。

**总结：**
部署植物的完整链路是：**网络输出一维最大值索引 -> 数学解码为三维坐标 (行,列,植物) -> 三重游戏规则校验 -> 校验失败则这局游戏直接暴毙 / 校验成功则修改矩阵状态、扣资源 -> 触发植物攻击与僵尸移动的结算。**

## 5. 结合真实手机环境的全流程部署（从画面到物理点击）
在目前的DQN代码中，训练和推演都在纯后端的虚拟矩阵中进行（无拖拽等物理动作）。如果将其接入真实的手机或模拟器客户端，完整的部署链路如下：

### 5.1 状态提取（获取真实画面）
- PC端利用 `adb shell screencap` 或投屏工具（如Scrcpy）获取游戏实时画面。
- 通过计算机视觉技术（OpenCV模板匹配、YOLO目标检测等），识别画面中的阳光数值、草坪上各格子的植物与僵尸分布，以及卡槽植物的冷却状态。
- 将这些视觉信息转化为DQN网络能够理解的 **3D矩阵结构 (`lawn`)** 和标量状态。

### 5.2 AI 思考并下达指令
- 将转换后的矩阵状态送入训练好的 DQN 网络。
- 神经网络输出最高Q值对应的索引，解码为逻辑动作指令，例如 `(行: 2, 列: 3, 植物: 豌豆射手)`。

### 5.3 指令转化为屏幕像素坐标
- 通过预先配置的多分辨率映射表，将逻辑指令转换为手机屏幕上的物理坐标。
- 例如，豌豆射手卡槽的坐标映射为 `(x1, y1)`，草坪第2行第3列的中心映射为 `(x2, y2)`。

### 5.4 真实物理部署（执行点击与拖动）
- AI 通过调用 Android 调试桥接（ADB）发送模拟触控指令完成操作：
  - **点击模式**：连续发送 `adb shell input tap x1 y1` 和 `adb shell input tap x2 y2`。
  - **拖拽模式**（一气呵成）：发送滑动指令 `adb shell input swipe x1 y1 x2 y2 300` 模拟长按拖拽部署。

## 6. DQN 模型的完整训练流程
在 `dqn_agent.py` 中，模型的训练过程采用了“虚拟沙盒试错 -> 存入错题本 -> 抽样复习更新”的经典机制，完整循环如下：

### 6.1 开启新对局 (Episode Initialization)
每次循环开始时，调用 `env.reset()` 清空虚拟草坪，重置阳光为初始值，植物冷却清零，分数归零。

### 6.2 观察局势与做决定 (Select Action)
采用 **ε-greedy (贪心探索) 策略**：
- **探索（瞎玩）**：初期概率 `epsilon` 很高，AI 随机选择动作（坐标与植物）。这会导致频繁因阳光不足或违规操作被扣分，但能探索各种可能。
- **利用（经验）**：随着训练进行，`epsilon` 逐渐衰减。AI 开始把当前画面输入给 **策略网络 (Policy Net)**，并严格执行预测 Q 值最高的动作。

### 6.3 与环境交互并获取反馈 (Env Step)
执行动作后，环境返回即时反馈：
- 计算得分（违规乱放扣分，打死僵尸加分）。a 
- 推进游戏时间（僵尸移动，产生下一个瞬间的画面状态 `next_state`）。
- 判断游戏是否结束（`done` 标志，如僵尸进屋）。

### 6.4 记入记忆池 (Replay Buffer)
AI 不会立刻用刚刚发生的一步更新网络，而是将这一个瞬间的完整经历 `(state, action, reward, next_state, done)` 打包，存入容量为数万条的记忆池中。

### 6.5 抽样复习与网络更新 (Train Step)
每次行动后调用 `train_step()` 进行复习：
1. **随机抽样**：从记忆池中随机抽取一批（如 32 或 64 条）过去的记忆。随机抽样打破了时间相关性，防止网络死记硬背（过拟合）。
2. **计算目标 Q 值 (Bellman Equation)**：利用另一个备用的 **目标网络 (Target Net)** 计算这批记忆中 `next_state` 的最大预期得分。计算公式为：`目标分数 = 真实奖励 + 衰减系数(gamma) * 目标网络预测未来分数`。
3. **反向传播修正**：让当前的 **策略网络 (Policy Net)** 计算当前状态的预测分。将预测分与刚才算出的“目标分数”计算均方误差（MSE Loss），并通过 Adam 优化器反向传播，微调网络参数。

### 6.6 知识巩固 (Target Update)
为防止目标标准频繁变动导致训练崩溃，设计了双网络结构。平时只更新 Policy Net；每隔固定步数（如 1000 步），将 Policy Net 学到的参数**直接硬拷贝（同步）**到 Target Net 中，确保训练目标的稳定性。
