## 一、 项目概述 (Project Overview)
本项目旨在解决复杂二次元塔防手游《明日方舟》的动态自动化部署问题。传统的自动化脚本（如 MAA）主要依赖固定的坐标轴流水线录制或严格的模板图像识别，缺乏应对复杂多变战局的泛化决策能力。
因此，本项目提出了一种**基于强化学习 (Reinforcement Learning, PPO 算法) 与混合机器视觉架构的智能体控制系统**。系统通过 YOLO 检测友方状态，通过 MOG2 背景建模构建“敌人动态雷达”，将游戏画面降维为 3 通道张量（灰度原图、部署网格掩膜、敌人雷达掩膜）。智能体通过马尔可夫决策过程（MDP）进行训练，能够自主决定在什么位置、以什么朝向部署干员，从而实现将卡牌“丢到敌人脸上并正对敌人”的战术动作。

## 四、 第三章 撰写指南：自动化部署系统核心架构设计

本章需要体现强大的工程落地能力和系统架构思维。

### 3.1 系统总体架构设计
描述系统的闭环运作流程：
1. **环境感知**：通过 ADB 协议获取模拟器截图。
2. **混合视觉特征提取**：利用 YOLO、MOG2 等技术提取特征。
3. **强化学习决策大脑**：PPO 神经网络根据特征输出离散动作。
4. **动作控制执行**：将动作翻译为划屏操作注入游戏。

### 3.2 混合视觉感知模块设计 (亮点)
*   **YOLO 干员状态检测**：阐述为何放弃模板匹配，转而用 YOLO 实时捕捉干员部署落地的血条中心点坐标，用于解决动态转场时的漏检问题（配合3次心跳检测机制）。
*   **MOG2 动态敌人雷达**：阐述提取背景极其复杂的游戏画面中移动敌人的方法。使用 `cv2.createBackgroundSubtractorMOG2` 提取前景，并辅以形态学滤波（开闭运算）消除特效干扰，提取敌人连通域质心。
*   **基于模板匹配的 UI 状态机导航**：简述利用 OpenCV `TM_CCOEFF_NORMED` 实现的关卡自动重启、界面跳转兜底逻辑。

### 3.3 强化学习马尔可夫决策过程（MDP）建模 (核心)
*   **状态空间 (State Space) 降维**：不使用原彩 RGB 图像，而是人工合成了高信息密度的 4 通道张量 $(C=4, H=72, W=128)$：
    *   Ch1: 游戏原画灰度图。
    *   Ch2: 提取特定地形先验的地图掩膜（基于 levels.json 的高低台与不可部署区域映射）。
    *   Ch3: 基于 MOG2 的敌人动态雷达 Mask。
    *   Ch4: 手牌区职业特征映射图（利用 OpenCV 亮度检测剔除冷却/无费卡牌，通过模板匹配识别干员职业，并赋予不同的灰度值以示区分）。
*   **动作空间 (Action Space)**：定义为 MultiDiscrete 离散空间，包含 12 个维度的选卡策略（精确对应 12 张卡位，移除了挂机动作）、10x5 的网格坐标选择、以及 4 个方向的朝向选择。
*   **基于空间几何的奖励函数重塑 (Reward Shaping, 重点创新)**：
    *   解释为何缩放奖励幅度以避免梯度爆炸（从 +100/-10 缩放至 +1.0/-0.05）。
    *   阐述密集型即时奖励公式：
        1. 基础惩罚/兜底：Action Masking（地形不可部署、费用不足/CD、格子已有友方干员）拦截扣 0.05 分。
        2. 部署成功奖励：基础 +1.0。
        3. 距离奖励：计算部署坐标与雷达探测到的敌人质心的欧氏距离，距离越近奖励越高（+0.5），过远惩罚（-0.2）。
        4. 朝向奖励：利用反正切函数 (`math.atan2`) 计算敌人相对于干员的角度，朝向一致奖励（+0.3），背对敌人予以微弱惩罚（-0.1）。

### 4.4 系统的局限性 (为第五章铺垫)
*   客观剖析：执行器噪声（Actuator Noise）对马尔可夫决策过程（MDP）的影响。由于安卓模拟器底层触控响应的不稳定，相同的拖拽动作有概率被游戏拒收（即“手滑”），导致环境呈现极度的非平稳随机性。
*   导致现象：智能体在遭遇大量由于手滑导致的虚假负反馈时，可能会陷入探索与利用困境（Exploration-Exploitation Dilemma），在评估模式下出现短期的局部最优死锁。受限于算力和训练时长，模型未能达到完美的收敛状态，但本课题搭建的“视觉-控制-训练”闭环框架充分证明了该技术路线的可行性，为后续基于更加稳定的 API 接口或延长训练周期提供了坚实的工程基础。
