# 明日方舟 RL 自动化端到端训练项目进度报告

## 📝 当前进度与已完成工作 (截至 2026-04-05)
我们彻底重构了底层环境架构，摒弃了严重依赖动态 CV 检测（绿网格）带来的状态迟滞和死循环问题，转而采用了 **混合架构：静态关卡先验 + 动态实时感知 + 高频异步监控**。目前这套系统已经能支撑彻夜训练而绝不死锁！

**具体完成的核心技术升级：**

1. **绝对的地形先验 (Topological Prior Mapping)**：
   - 引入了 `Arknights-Tile-Pos-main/levels.json` 数据。
   - 在 `game_env.py` 的 `_init_level_prior` 中，将关卡（如 1-7）的 JSON 地图数据解析为与 AI 动作空间绝对对应的 5x10 静态沙盘矩阵（黑=不可部署，白=低台，灰=高台）。
   - 将这层先验地图重采样至 1280x720，作为独立的通道输入到 PPO 的 CNN 网络中，从根本上解决了 AI“看不到哪里能部署”的痛点。

2. **动作掩码与规则前置拦截 (Action Masking & Heuristic Penalty)**：
   - 将部署动作验证与模拟器物理滑动彻底解耦。
   - **黑名单秒杀**：当 AI 选中“黑块（深渊/不可部署）”时，环境**不执行任何模拟器操作**，直接前置拦截并给予极度严厉的 `-15.0` 惩罚。极大加速了早期瞎玩阶段的试错效率。

3. **物理执行：“盲狙” + 血条验证 (Blind Deployment & HP Bar Verification)**：
   - 当 AI 选中合法（白/灰）格子时，系统放弃了慢速的“点开看绿光”，改为极速的“一笔画盲狙滑屏”。
   - 拖拽后，环境使用 YOLO 侦测全屏是否出现了干员独有的 `operator_hp_bar`（绿色血条）。
   - **逻辑闭环**：如果不出现血条（说明费用不足、技能冷却、或者高低台违规），则扣除 `-2.0` 分，并**强制触发 `time.sleep(2.0)`** 让游戏时间流逝，以此积攒费用并打破循环死锁。

4. **主线程污染防御：小弟打饭模式 (Asynchronous High-Frequency Monitor)**：
   - 注入了专职的后台看门狗线程 `_battle_monitor_worker`。
   - 以不阻塞主线程的速度（约 3Hz），死死盯住右上角的“暂停齿轮”（ROI圈定，阈值提高至 0.6），以及画面的 MSE 剧变。
   - 一旦发现游戏在后台结算了（连续两次没看到齿轮或 MSE > 8000），立刻拉响 `_emergency_stop_flag` 警报。主线程瞥见警报后瞬间中断当前回合，完美防止了在结算界面“挥空拳”导致的奖励噪声污染。
