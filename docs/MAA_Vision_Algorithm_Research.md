## 摘要
MaaAssistantArknights (MAA) 是一个高度复杂且稳定的自动化工具。为了应对不同分辨率、渲染差异以及复杂的动态游戏场景，MAA 并没有依赖单一的图像识别技术，而是构建了一套**混合计算机视觉架构**。本报告详细解析了其核心视觉识别算法及其保证高精准度的策略。

## 1. 模板匹配系统 (Template Matching)

对于固定的 UI 元素（如图标、静态按钮、固定的界面结构），MAA 主要依赖 OpenCV 提供的模板匹配算法，并在此基础上进行了大量的创新优化。

### 1.1 核心算法：归一化相关系数匹配
系统底层固定使用了 OpenCV 的 `cv::TM_CCOEFF_NORMED`（归一化相关系数匹配）算法。该算法能有效抵抗一定的全局光照变化，返回介于 -1 到 1 之间的相似度得分（1 为完美匹配）。

### 1.2 提升精度的创新策略
由于游戏 UI 经常带有半透明背景或动态特效，单纯的 `TM_CCOEFF_NORMED` 容易产生误判。为保证极高的精准度，项目采用了以下机制：

*   **带掩码的模板匹配 (Masked Matching)**
    系统允许在任务配置中设置灰度或颜色的范围（`mask_ranges`）。在执行匹配前，会利用 `cv::inRange` 等函数提取出目标主体的二进制掩码（主动忽略透明或无关的背景区域），将其传入 `cv::matchTemplate`。这意味着算法只比较 UI 主体的有效形状，彻底隔绝背景干扰。
*   **自适应阈值判定**
    针对不同的 UI 元素配置不同的相似度阈值（Threshold）。只有最高得分大于设定阈值的匹配结果才会被视为有效定位。
*   **F1-Score 颜色特征校验 (RGBCount / HSVCount)**
    这是该项目避免混淆相似 UI 的核心技术。针对容易误判的元素，系统会在结构匹配之后进行二次颜色空间校验：
    1. 提取模板与当前屏幕画面的特定颜色掩码。
    2. 利用互相关算法 `cv::TM_CCORR` 作为卷积操作，统计两者颜色重叠部分的“真阳性(TP)”和“假阳性(FP)”像素数。
    3. 根据像素统计结果，计算该特征颜色分布的 **F1-Score**。
    4. 将第一步的结构匹配得分与 F1-Score **相乘**得出最终得分。这确保了目标不仅在形状上吻合，在特定的特征颜色分布上也必须严丝合缝。

## 2. 特征点提取与匹配 (Feature Matching)

在一些复杂的战斗场景或动态特效强烈的环境中，目标物体可能发生轻微的缩放、旋转或被严重遮挡。针对这类模板匹配容易失效的场景，系统使用了传统的特征工程方法。

### 2.1 核心算法
系统支持多种经典的特征提取算法，包括但不限于：
*   **SIFT** (尺度不变特征变换)
*   **ORB** (Oriented FAST and Rotated BRIEF)
*   **BRISK**, **KAZE**, **AKAZE** 等。

### 2.2 鲁棒性保障 (RANSAC)
*   系统提取目标的“关键点（Keypoints）”和“描述子（Descriptors）”后，使用 `FlannBasedMatcher` 或 `BFMatcher` 计算相似度进行配对。
*   为解决特征匹配极其容易产生大量错误连线（Outliers）的问题，系统引入了 **RANSAC (随机抽样一致性)** 算法，并结合 `cv::findHomography` 计算单应性矩阵。这一组合能有效剔除错误的匹配点，确保即使在强干扰下也能准确定位目标的透视变换位置。
